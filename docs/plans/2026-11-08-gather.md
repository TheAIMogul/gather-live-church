# Gather Implementation Plan

**Goal:** Build the approved warm, glossy bilingual church experience as a deployable Cloudflare application.

**Architecture:** React serves operator, branding, phone microphone, and audience routes. A Cloudflare Worker authenticates operators, mints scoped links and short-lived OpenAI credentials; a Durable Object per service persists branding and synchronizes bounded caption history over WebSockets. Browser WebRTC carries audio directly to OpenAI. Contextual phrase interpretation and summaries run server-side; no raw audio is stored.

**Tech Stack:** TypeScript, React, Vite, Cloudflare Workers/SQLite Durable Objects, OpenAI Realtime translation and Responses, Vitest, Playwright.

## 1. Foundation
- Create package, strict TypeScript, Vite, Wrangler static assets and Durable Object migration.
- Initialize isolated Git repository and ignore secrets/build output.
- Install dependencies; verify build and Worker dry run.

## 2. Shared live room
- Implement shared types, authenticated API, scoped display/microphone tokens, persistent branding, bounded caption state, WebSocket broadcasts.
- Validate body sizes and controls, forbid viewer writes, protect cookie mutations against cross-origin requests.
- Verify auth, viewer isolation, phrase ordering, pause/clear, and persistence against local Worker.

## 3. OpenAI processing
- Verify current official schemas before implementation.
- Mint ephemeral WebRTC credentials; collect source phrase deltas and interpret complete phrases with recent context.
- Return structured translation, speech/scripture/paraphrase classification, possible reference and verification state.
- Never label model inference as a verified Bible quotation. Summarize independently, bounded input, safe failure state.

## 4. Product UI
- Create operator, branding settings, full-screen projection, and paired phone microphone routes.
- Match approved frosted ivory/sage/orange styling; words enter in readable phrase choreography, scripture uses gold with accurate confidence labels.
- Add input meter, microphone picker, pause/stop/blank, language direction, QR/link pairing, logo preview/save, persisted themes, reduced motion and responsive layouts.
- Include a clearly marked interactive demo that requires no API credentials.

## 5. Validation and delivery
- Run TypeScript, unit tests, Worker bundle, local API integration and browser journeys where browser infrastructure is available.
- Review security, lifecycle, reconnect, projected readability and mobile layout; repair findings.
- Document local setup, Cloudflare deployment, privacy/retention, capabilities, costs and pilot limitations. Add MIT license and contribution guide.
- Deploy to authorized Cloudflare account if credentials permit; verify live HTTP/auth/assets. Keep standard API key only in Worker secrets.
